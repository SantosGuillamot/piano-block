# Piano Block pipeline conventions

## Managing tasks

All tasks are tracked as **GitHub issues**, which are the single source of truth. Issue status is tracked with **GitHub labels** on the issue itself.

- **GitHub**: https://github.com/SantosGuillamot/piano-block — accessed via the `gh` CLI.

### Labels

The workflow relies on three families of labels. They must already exist in the repository before a run.

- **Phase status** — mutually exclusive; an issue carries **exactly one** at a time: `0 - Intent`, `1 - Spec`, `2 - Design Doc`, `3 - Plan`, `4 - Code`, `5 - Docs`, `PR opened`.
- **Run state** — `running…`; present only while a run is actively in progress.
- **Pipeline version** — mutually exclusive; **exactly one**: `v1`, `v2`, `v3`, …

GitHub labels are not inherently single-valued, so the orchestrator enforces the "exactly one" rule for the phase-status and version families itself: remove the current label in the family before adding the new one.

### Creating an issue

Create the issue in GitHub with `gh` (e.g. `gh issue create`), following the issue format in the radical-pipelines skill's `reference/manage-issues.md`.

### Modifying an issue

Edit the GitHub issue with `gh issue edit`.

### Orchestrator updates during a run

In addition to the normal pipeline workflow, the orchestrator keeps the issue's labels in sync with pipeline activity and pushes the pipeline branch at the end of every run. All label operations use `gh issue edit <number> --add-label / --remove-label`.

- **At run start** — add the `running…` label before launching anything: `gh issue edit <number> --add-label "running…"`.
- **At run end** — remove the `running…` label. This applies to every outcome: normal close-out, blockers, owner-cancelled runs, and failures.
- **Push at run close-out** — push the pipeline branch to the remote. This happens after the final commit of the run has landed locally and applies to every outcome: normal close-out, blockers, owner-cancelled runs, and failures.
- **When a phase finishes** — move the phase-status label to the phase that just satisfied its completion predicate: `0 - Intent` after the pipeline is created, then `1 - Spec`, `2 - Design Doc`, `3 - Plan`, `4 - Code`, `5 - Docs` as each phase completes. Remove the previous phase-status label and add the new one so the issue always carries exactly one. Update the label **immediately when the phase finishes**, before launching the next phase — never wait until the end of the run.
- **When the PR is opened** — move the phase-status label to `PR opened`, the terminal label for a successful pipeline.
- **Pipeline version label** — when starting work on a pipeline (creating, resuming, or forking), make sure the issue carries exactly one version label matching the active pipeline (`v1`, `v2`, …). Remove any other version labels first, then add the current one if it isn't already present.

These updates apply to both autonomous and assisted runs.

## Pipeline slugs

Use `<issue-number>-<short-description>` where `issue-number` is the GitHub issue number.

## Artifact folders

Use `.rp/pipelines/<pipeline-slug>`.

## Commit format

Use imperative mood, sentence case, no period at the end. Include the name of the agent in parentheses.

Examples:

- `Add intent (orchestrator)`
- `Add spec (spec-reviewer)`
- `Support for X (implementer)`

## Claude Code worktrees

Folder: `.claude/worktrees/<pipeline-slug>`
Enter worktree: `EnterWorktree` with name: `<pipeline-slug>`
Exit worktree: `ExitWorktree` with name: `<pipeline-slug>`

## Branch names

Created automatically by `EnterWorktree`: `worktree-<pipeline-slug>`

## Team spawning

Use `TeamCreate`.

## Health monitoring

Use Claude Code's bundled `/loop` skill — no install required. Only the autonomous workflow launches the monitor; assisted runs do not.

- **Start:** `/loop 5m <prompt>` where `<prompt>` is the template from the radical-pipelines skill's `reference/health-monitoring.md`.
- **List active loops:** `/loop-list`.
- **Cancel:** `/loop-kill <id>` using the id returned at start.

The orchestrator starts the loop itself.
