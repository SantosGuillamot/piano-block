## The headline deviation — adjudicated and CONFIRMED

**T4 added `@wordpress/icons ^10.32.0` to `package.json` `dependencies`, contradicting the plan's T3 note ("build-externalized, no package.json change").** I independently verified the orchestrator's adjudication and concur the plan's note was factually wrong:

- `build/index.asset.php` lists externalized handles `react-jsx-runtime, wp-block-editor, wp-blocks, wp-components, wp-element, wp-i18n, wp-primitives` — there is **no `wp-icons` handle**. `DependencyExtractionWebpackPlugin` does NOT externalize `@wordpress/icons`.
- The icon SVG path data is **bundled into `build/index.js`** (`d:"M…"` path attributes are present there; `grep -c wp-icons build/index.asset.php` returns 0). `wp-primitives` (the SVG primitive the icons render through) IS externalized, but the icon components/paths themselves are compiled in.
- So without the dependency the icon imports would not resolve at build time. Adding it is the correct fix, and it satisfies the **spec's actual constraint** — R-E2 / AC-A1 require "only `@wordpress/*` packages that WordPress already provides." `@wordpress/icons` ships with WordPress core (it is a first-party `@wordpress/*` package, available to blocks at runtime via the bundled paths), so this is compliant. It is NOT an "outside runtime dependency."

This is the right call. The plan's prose was the error; the code corrected it.
