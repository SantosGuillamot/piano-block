# Doc Plan Review

## Verdict: approved

## Summary

The doc plan is sound, complete, traceable, and drift-resistant, and I am approving it. All four tasks are self-contained with the seven required fields (Goal / Audience / Files / Sections-scope / Depends on / Traces to / Acceptance). I verified every file path, line number, and section name the plan cites against the real worktree: `docs/song-format.md` (the `event :=` block ~161-170, the `chordSymbol` bullet at line 178, the single-event example at line 183, the `measures` section ~67-82, the "Additive growth" section, and the "Annotated example song" section with its intro at line 272 and its `"chordSymbol": "C"` at line 298) and `README.md` (the script-breakout-escape paragraph at line 162 under `## For contributors` → `### The song format and validator`, naming both `chordSymbol` and `metadata.title`). A repo-wide sweep confirms the plan's coverage claims: the only feature-relevant doc surfaces carrying the changed behavior are `docs/song-format.md` and `README.md`; `AGENTS.md`, `src/notation/OFL.txt`, and the root `.rp.md` carry no `chordSymbol`/annotation/song-format reference and correctly need no task. Coverage is complete — the per-event and standalone `notes` model, placement/staff/beat semantics with enums and defaults, the four grand-staff positions, free-text verbatim semantics, the spec Requirement 8 migration line, and the spec Requirement 6 token-removal (with the single documented migration-line exception) are all owned by a task. The plan correctly enforces the code/docs split: every task instructs the writer to author against the FINAL shipped code (the schema's future `eventNote`/`standaloneNote` `$defs` and `event.notes`/`measure.notes` attachment points, read from `src/song/schema.js`), respecting that the Docs phase runs after the Code phase, and it explicitly lists the out-of-scope behaviors not to document. There are no code tasks, no scope creep, and no hard-coded internal implementation details (function names, parameter lists, return shapes) that could drift — the only field names cited (`text`, `placement`, `staff`, `beat`, `notes`) are the spec's fixed author-facing data-model contract, and each acceptance criterion defers final naming to the shipped schema.

## Partition check

Tasks 1, 2, and 3 all edit `docs/song-format.md`, but Sections-scope partitions them: Task 1 owns the Events and `measures` sections (and a conceptual passage kept inside them); Task 3 owns only the "Annotated example song" section; Task 2 adds a single migration line. The tasks run sequentially (Task 2 and Task 3 both depend on Task 1), so no two writers collide concurrently, and the apparent token-policy tension (Task 1's "no `chordSymbol` token in any section this task touches" vs. Task 2's later insertion of the one permitted `chordSymbol` migration line) is reconciled by the dependency ordering and Task 2's explicit "only place" carve-out. Task 4 is an independent file.
