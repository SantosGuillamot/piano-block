## Accuracy / no drift — verified against shipped code and a live run

- **Command name.** Docs document `npm run plugin-zip`; `package.json` defines
  `scripts.plugin-zip`. Exact match. The three stage names the README cites
  (`npm run build`, `scripts/check-build.js`, `wp-scripts plugin-zip`) match the
  actual chain string
  `npm run build && node scripts/check-build.js && wp-scripts plugin-zip`.
- **Live run.** `npm run plugin-zip` exits 0 and writes `piano-block.zip` at the
  repo root. `unzip -l` shows every entry under a single `piano-block/` root and
  exactly the documented payload: `piano-block.php`, `README.md`, all `build/**`
  (`block.json`, `render.php`, `index.js`, `view.js`, `style-index.css`,
  `style-index-rtl.css`, `index.asset.php`, `view.asset.php`) and a
  `build/fonts/*.woff2`. None of the documented-excluded paths leaked (no `src/`,
  `node_modules/`, `package.json`, `scripts/`, config, or process files). A
  second run overwrote cleanly (idempotency claim holds).
- **Guard description.** `scripts/check-build.js` checks exactly
  `build/block.json` existence and nothing more. Verified the three cases in an
  isolated dir: no `build/` → exit 1 (stderr message); `build/` with fonts but no
  `block.json` → exit 1; `block.json` present → exit 0. The README's "Why the
  guard checks `build/block.json` specifically" para (keystone + partial-build /
  surviving-fonts rationale) is accurate and does **not** overstate — it makes no
  claim about validating `languages/` or running e2e tests.
- **Include/exclude framing.** Documented as an allowlist of the standard
  WordPress plugin layout with exclusion as the default and new `build/**` files
  auto-captured — matches the archiver's real allowlist behavior (confirmed by
  the run's "Using Plugin Handbook best practices to discover files" output).
- **`files`-field constraint.** `package.json` has **no** `files` field today, so
  the doc describes the real, relied-upon state; the stated consequence (allowlist
  vs. npm `files`-driven selection) matches the design doc's analysis of the tool.
- **Git-ignore note.** `.gitignore` carries the anchored single-file rule
  `/piano-block.zip` (line 13) with its comment
  `# Distribution artifact (generated by \`npm run plugin-zip\`)`.
  `git check-ignore -v piano-block.zip` → `.gitignore:13:/piano-block.zip`. The
  README correctly describes a git-ignored single artifact, never a broad `*.zip`.
  After a real run, `git status --short` does not list the zip.
- **Version claim.** "WordPress 6.9+ / PHP 7.4+" in the new prose matches the
  plugin header (`piano-block.php`) and the existing Requirements section — not
  invented.
